# 冻结原策略的抖动物理诊断

## 问题和当前边界

原110/control2500保持32/32初态走满60秒，但5秒、29–30秒、48秒及其它时刻的
抖动尚未解决。加强全关节/子步/踝部奖励和目标滤波的既有候选均未通过质量门禁，
不能以训练正常结束或指令高频下降宣称处理完成。域随机化、观测噪声继续关闭。

原reference/env0的5.33→5.34秒，右足竖直速度−0.529→+0.427m/s、净Fz
0→5076N，同步出现关节加速度尖峰；双足几何距离约105mm，足与躯干约452mm，
支持落脚冲击关联，不是接触对身份的直接证明。29.35–29.37秒的AABB间隔约4.4mm
是包围盒虚近：凸包法向分离下界约85mm，不能作为脚部自碰撞证据。
47.43秒双足间隔约163mm。强力帧之外仍存在明显振动，冲击不是全部问题。
输入证据为`outputs/amp-jitter/baseline-110-v2/reference_env0_signals.npz`及逐帧曲线。

训练奖励也存在解释边界：动作一/二阶差分对带探索噪声的采样动作收费，而部署使用
网络均值。额外踝部惩罚使探索std下降，但确定性全关节差分并未改善。
无新奖励的续训也出现均值策略漂移，因此本轮不更新任何网络，先隔离物理因素。

不能要求它仍相等。另保留warmup后的initial_*，其中original需与原归档逐位对齐。

## 记录和验收

每个控制周期为env0记录10个子步的12关节速度、实际力矩，以及躯干/双足的
净接触力和13维刚体状态。同步保留全部16环境的子步加速度平方、峰值、
力矩变化和足部净Fz峰值，物理历史在重置后的保护区间无效。
额外回读actor碰撞shape属性、body→shape范围和实际sim参数；API不提供的属性
保留null，不能用配置名或零值伪装为已测参数。净力不能确定接触对或完整摩擦力。

离线审计逐项检查源SHA/网络加载、相同代码/URDF/PD/初态、单参数差异、
原始子步与汇总/端点一致、32条共同有效前缀（剔除失败末1秒）的加速度/力矩/
动作频谱/滑移/航向，以及双方都无强力尖峰的相同时间段。
另逐一检查4–6、28–31、47–49秒及最坏窗口。原参数记录还需与原归档回放对齐，
验证只读采样没有改变被测行为。物理对照只支持后续干预选择，不能单独证明抖动修复。
